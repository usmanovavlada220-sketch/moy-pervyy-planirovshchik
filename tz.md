# Техническое задание на личный планировщик

Версия 2.0. Дата - 24 октября 2026 года. Включены согласованные дополнения и финальная сверка. Статус реализации и доказательства проверок находятся в plan.md; версия ТЗ не означает завершённую приёмку Safari.

## 1. Статус документа и приоритет требований

Этот документ является самостоятельным заданием для разработки. Он заменяет противоречащие ему положения `concept.md`. Концепцию не переписывать. Разработать приложение только после отдельного поручения пользователя; подготовка этого ТЗ не является поручением писать код.

Последние согласованные изменения относительно концепции.

- План недели является общим изменяемым списком, без кнопки фиксации первоначального плана.
- Прошлые недели можно исправлять.
- Нужны поиск по названию и описанию, копирование, корзина и восстановление.
- Для встреч нужны предупреждение об одинаковом времени и напоминание за 15 минут.
- Нужны настройка цветов, светлая и тёмная темы.
- Первый запуск показывает пустой планировщик.

Все численные ограничения, значения по умолчанию и правила исключительных ситуаций ниже являются проектными решениями этого ТЗ. Они заданы для однозначной реализации и не выдаются за отдельные дословные пожелания пользователя.

## 2. Назначение и результат разработки

Личный планировщик для одного человека на Mac. Пользователь планирует рабочие и личные задачи по неделям, ведёт отдельные встречи, видит месяц целиком и итоги выполнения. Задачи распределяются по статусам, а не по дням недели.

Результат будущей разработки - ровно три файла приложения в одной папке.

| Файл | Назначение |
| --- | --- |
| `index.html` | Разметка, встроенные в разметку иконки, подключение стилей и скрипта |
| `style.css` | Вся визуальная система, темы и адаптация размеров окна |
| `script.js` | Логика, встроенные фразы, хранение, импорт и экспорт |

Документы `concept.md` и `tz.md` не являются файлами приложения. Не требовать установки пакетов, сборки, терминала, сервера или подключения к интернету. Применять обычные HTML, CSS и JavaScript, без внешних библиотек, CDN, внешних шрифтов и изображений. Скрипт подключать как обычный скрипт с `defer`, без модулей и загрузки локальных ресурсов через `fetch`.

Основной запуск - двойной щелчок по `index.html`, открывающий страницу браузера. Упоминание пользователем заметок трактуется как возможность хранить ссылку на файл; интеграция с Apple Notes не предусмотрена. Все три файла должны оставаться рядом. Встроенная помощь объясняет это без технических инструкций.

## 3. Пользователь, права и автоматические действия

Одна роль - владелец планировщика. Нет регистрации, пароля, приглашений, других ролей или совместного редактирования.

Владелец может создавать, просматривать, искать, редактировать, завершать, копировать, переносить и удалять задачи; восстанавливать архив и корзину; управлять встречами; исправлять исторические сводки; менять оформление; экспортировать и импортировать данные.

Автоматическая логика приложения выполняет сохранение, переход между неделями, перенос незавершённых задач, расчёт показателей, напоминания в работающей странице и смену фразы дня. Это не отдельный пользователь.

Имена в поле «от кого жду / кого контролирую» являются обычным текстом. Указанные люди не получают доступа, уведомлений или сообщений.

## 4. Среда, границы и подтверждённые ограничения

### 4.1. Поддерживаемая среда

- macOS, Safari и Google Chrome.
- При приёмке записать фактически проверенные версии macOS и обоих браузеров. Их номера сейчас неизвестны, поэтому не выдумывать их.
- Основное окно - 1280 × 800 CSS-пикселей и больше. Дополнительные размеры и правила адаптации заданы в разделе 17.1.
- Поддерживаемая платформа остаётся macOS. Компактная вёрстка пригодна для узких окон и сенсорного управления, но проверка запуска локальных файлов в iPadOS/iOS не входит в обязательный объём; не заявлять поддержку этих систем без отдельной проверки.
- Интерфейс полностью на русском языке, время в формате 24 часов.
- Неделя начинается в понедельник. Календарные даты используют местное время компьютера.

### 4.2. Хранение локального файла

Использовать localStorage. Данные разных браузеров и профилей не объединяются. Перенос между Safari и Chrome выполняется через экспорт и импорт.

Поведение localStorage для `file:` не стандартизовано. Сохранение при прямом открытии файла должно быть фактически проверено в обоих целевых браузерах. Не обещать одинаковое поведение при перемещении или переименовании папки. Если хранение недоступно, показать режим временной работы и предложить экспорт. Источник - [MDN о localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage).

### 4.3. Напоминания и звук

Напоминания гарантируются только в пределах проверенного поведения открытой активной страницы на бодрствующем компьютере. Фоновые таймеры могут задерживаться. После возвращения к странице приложение перепроверяет время. Источник - [MDN о таймерах](https://developer.mozilla.org/en-US/docs/Web/API/Window/setTimeout).

Звук требует пользовательского действия для активации и может блокироваться браузером. Всегда оставлять визуальное напоминание. Источник - [MDN об автоматическом воспроизведении](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay).

Системные уведомления через Notifications API не являются обязательной частью этой версии. Их поддержка и разрешения зависят от браузера и контекста запуска. Не запрашивать разрешения при старте. Источник - [MDN о Notifications API](https://developer.mozilla.org/en-US/docs/Web/API/Notifications_API).

### 4.4. Виджет рабочего стола

Пользователь хотел бы настоящий виджет macOS. Он не реализуется в обязательном объёме трёх локальных файлов. Документация Apple описывает нативный путь через приложение и расширение WidgetKit. Вывод для проекта - такой путь требует отдельного объёма разработки. Источники - [WidgetKit](https://developer.apple.com/documentation/widgetkit), [создание расширения виджета](https://developer.apple.com/documentation/widgetkit/creating-a-widget-extension).

В этой версии реализовать компактный режим встреч в той же странице. Он не называется системным виджетом, не закрепляется поверх окон и не обещает работу при закрытом браузере.

### 4.5. Не входит в объём

Нет серверов, баз данных, облачной синхронизации, интеграций с календарями, повторяющихся встреч, вложений, загрузки изображений, проектов внутри рабочих задач, автоматического распределения по дням, оценки трудозатрат, совместной работы и нативного приложения. Не добавлять скрытые сетевые запросы, аналитику посещений или отправку данных третьим лицам.

## 5. Структура интерфейса

### 5.1. Главный экран недели

Верхняя панель содержит название «Мой планировщик», диапазон недели, стрелки перехода, кнопку «сегодня», переключатель «неделя / месяц», поиск, кнопки добавления задачи и открытия настроек.

Левая панель шириной 260-300 пикселей содержит мини-календарь месяца, список встреч выбранной недели, кнопку добавления встречи и переход в компактный режим встреч. Точки на датах обозначают наличие встреч. Выбор дня выделяет и прокручивает соответствующую группу встреч. Двойной щелчок по дню не обязателен; отдельная кнопка создания доступна всегда.

Основная область содержит цель недели, отключаемую фразу дня, фильтры, компактную строку показателей и четыре колонки задач. Под колонками расположен сворачиваемый общий раздел «позже».

Кнопки «архив», «корзина», «итоги», «резервная копия» доступны из постоянного меню. Ни одна важная функция не доступна исключительно через наведение мыши.

### 5.2. Другие представления

- Месяц - карточки недель со списками задач и показателями.
- Прошлая неделя - сводка с кнопкой «исправить сводку» вместо активной доски.
- Архив - завершённые задачи.
- Корзина - удалённые задачи.
- Поиск - результаты по всем периодам.
- Карточка задачи - панель справа; на узком окне полноэкранная панель.
- Форма встречи - диалог.
- Настройки - оформление, напоминания, резервные копии и помощь.
- Компактные встречи - список ближайших встреч и кнопка возврата к доске в той же вкладке.

Переключение представлений не перезагружает страницу. Новый запуск открывает текущую неделю, даже если перед закрытием была открыта другая. Тема и настройки сохраняются; поисковый запрос и временные фильтры при новом запуске очищаются.

## 6. Задачи

### 6.1. Поля и ограничения

| Поле | Правило |
| --- | --- |
| Название | Обязательное, 1-200 символов после удаления крайних пробелов |
| Описание | Обычный текст, до 10 000 символов, переносы строк сохраняются |
| Тип | `work` или `personal`, по умолчанию рабочая |
| Статус работы | `new`, `in_progress`, `waiting`, `control` |
| Размещение | Конкретная неделя либо общий список `later` |
| Срочность | Булево значение, по умолчанию выключено |
| Срок | Необязательная календарная дата без времени |
| Контакт | Обычный текст, до 200 символов |
| Чек-лист | До 100 пунктов, текст пункта 1-300 символов |

Не добавлять поле проекта, исполнителей с аккаунтами, теги произвольной структуры или обязательную оценку сложности.

Видимые колонки - «новые», «в работе», «жду ответ», «на контроле». «Позже» является размещением, а не пятым статусом работы. Это позволяет отправить задачу в «позже» и сохранить её рабочий статус. При первом создании в «позже» статус `new`.

Срочность не зависит от срока или статуса. Просрочка вычисляется, а не задаётся пользователем. Цвет не служит единственным обозначением.

### 6.2. Создание и редактирование

Глобальная кнопка добавления открывает форму со значениями «рабочая», «новые», выбранная текущая или будущая неделя. Если открыта прошлая сводка, новая обычная задача создаётся в текущей неделе с явной подписью. Добавление в исторический план является другим действием из режима исправления сводки.

Кнопка внутри колонки подставляет её статус. Кнопка в «позже» подставляет соответствующее размещение. При активном фильтре типа новая задача получает этот тип. Другие фильтры не меняют исходные значения.

Новая задача появляется только после кнопки «создать». Закрытие формы с непустым черновиком спрашивает, нужно ли его отбросить. Для существующей карточки корректные изменения сохраняются после паузы ввода 400 мс либо ухода с поля, что наступит раньше. Перед закрытием панели принудительно сохранить корректные изменения.

Пустое название и превышение лимита показывают ошибку около поля; последнее корректное состояние остаётся сохранённым. Не обрезать текст молча. Пока есть некорректные изменения, закрытие панели предлагает вернуться к форме либо отбросить только несохранённые изменения.

Название на доске занимает не более трёх строк, полное видно в карточке. Дополнительные элементы - тип, срочность, срок, контакт при наличии, счётчик чек-листа и счётчик автоматических переносов. Описание на доске не обязательно показывать.

### 6.3. Срок

Срок включителен. Задача со сроком 10 октября становится просроченной 11 октября в 00:00 местного времени, если не завершена и не удалена. Задача без срока не просрочена. В «позже» просрочка тоже видна, но не входит в недельные показатели.

Если срок вне назначенной недели, показать неблокирующее предупреждение «срок находится вне выбранной недели». Разрешить сохранение. Изменение недели не меняет срок автоматически.

### 6.4. Чек-лист

Можно добавлять, переименовывать, отмечать, удалять и переставлять пункты кнопками вверх и вниз. Пустой черновик пункта не сохраняется. Прогресс равен числу отмеченных пунктов из общего числа.

Отметка всех пунктов не завершает задачу автоматически. Если при завершении остаются неотмеченные пункты, спросить «завершить задачу с незакрытыми пунктами?». Подтверждение завершает только задачу, не меняя отметки пунктов.

### 6.5. Перетаскивание и порядок

Перетаскивание доступно за отдельную ручку, чтобы текст можно было выделять. Между колонками меняет статус; внутри колонки меняет порядок. Состояние сохраняется после успешного отпускания. Escape отменяет перенос.

Перенос между доской и «позже» меняет размещение. Возврат из «позже» в конкретную колонку задаёт её статус и открытую неделю. В меню карточки есть эквиваленты «сменить статус», «выбрать неделю», «отложить», «поднять», «опустить».

При поиске или фильтре типа, срочности, просрочки либо переноса перетаскивание и ручная перестановка отключены с подписью «сбросьте фильтры, чтобы изменить порядок». Сменить статус и неделю через меню по-прежнему можно. Это исключает неоднозначность порядка скрытых карточек.

Новые карточки, ручные переносы и копии добавляются в конец целевой колонки. Автоматически перенесённые задачи добавляются после уже запланированных, с сохранением взаимного порядка внутри каждого статуса.

### 6.6. Копирование

«Создать копию» доступно у активной и архивной задачи, но не у корзины или исторической строки. Открыть форму с названием «Копия - …», обрезав только предложенное название до 200 символов, и разрешить изменить его до создания.

Скопировать описание, тип, срочность, контакт и тексты чек-листа. Все пункты новой копии не отмечены. Сбросить срок, счётчик переносов, историю, дату завершения; статус `new`, размещение - выбранная текущая/будущая неделя либо текущая, если открыта история. Новая копия получает новый идентификатор только при подтверждении создания.

### 6.7. Завершение и архив

Кнопка завершения доступна в карточке и на доске. Задача исчезает из активного списка и появляется в архиве. Для завершения из «позже» назначить текущую неделю в качестве недели результата и включить задачу в её план. При завершении задачи, назначенной на будущую неделю, сначала перенести её в текущую и затем завершить. Показать это правило в подтверждении такого действия.

После завершения показать кнопку «отменить завершение» без таймера. Хранить в памяти только прежнюю карточку и затронутые строки недель, а не копию всего приложения. Отмена возвращает их состояние до завершения, включая прежнее размещение. Кнопка доступна до следующего изменения данных пользователем, обработки смены недели, импорта, конфликта вкладок или перезагрузки. Просмотр, поиск, фильтрация и отметка показа напоминания её не сбрасывают. При отмене применить обратное изменение к текущему состоянию через обычное сохранение, не откатывая чужие сущности. После сброса этой возможности использовать восстановление из архива.

Архив отсортирован по дате завершения от новых к старым. Доступны просмотр, изменение текста, копирование, восстановление и удаление. Редактирование архивной карточки не меняет автоматически прошлые сводки. Это явно написано в панели.

Восстановление предлагает текущую или будущую неделю, возвращает последний рабочий статус и сохраняет чек-лист. Если задача была завершена в ещё открытой текущей неделе, убрать её выполненность из этой недели. Если завершена в закрытой неделе, оставить историческое завершение и добавить задачу как новую работу выбранной недели. Поэтому одна длительная задача может иметь результаты в разных неделях, но не дублируется внутри одной недели.

### 6.8. Корзина

«Удалить» перемещает задачу в корзину после подтверждения. Для активной задачи её открытая плановая запись становится снятой с плана. Для архивной задачи исторический результат сохраняется. Удаление не означает выполнение.

Хранить прежнее состояние для восстановления. Незавершённая задача восстанавливается в выбранную текущую/будущую неделю либо в «позже». Завершённая восстанавливается в архив с прежней датой завершения. Если её удаление меняло открытую плановую запись, восстановить соответствующее участие и результат.

Автоматического очищения корзины нет. «Удалить окончательно» и «очистить корзину» требуют подтверждения. Исторические снимки остаются как самостоятельные данные сводок. Ссылку «открыть карточку» показывать только если задача с тем же идентификатором ещё существует; отдельный флаг наличия карточки не хранить. Окончательное удаление карточки не стирает итоги прошлых недель. Если нужно убрать историческую строку, это делается отдельно через исправление сводки.

## 7. Недели, общий список и переносы

### 7.1. Единая идентичность недели

Идентификатор недели - локальная календарная дата её понедельника в формате `YYYY-MM-DD`. Воскресенье принадлежит предыдущему понедельнику. Неделя на границе месяца или года остаётся одной сущностью и видна в обоих месяцах при пересечении.

Использовать встроенные `Date` и `Intl.DateTimeFormat("ru-RU", …)`, без сторонних библиотек. `Intl` отвечает за отображение дат, а не за разбор ввода и арифметику. Разбор `YYYY-MM-DD` выполняет один общий помощник - извлекает год, месяц и день, создаёт локальный `Date` и сверяет компоненты через `getFullYear`, `getMonth`, `getDate`. Для сдвига дней использовать `setDate`, для понедельника - `getDay`. Все операции собрать в небольшом общем наборе функций, а не повторять в обработчиках интерфейса.

Для календарной арифметики использовать локальный полдень, срок сравнивать как нормализованную строку даты, момент встречи создавать отдельно с её часами и минутами. Не использовать `new Date("YYYY-MM-DD")`, `toISOString().slice(0, 10)` для локальной даты или прибавление фиксированных миллисекунд вместо календарных дней. Источник о назначении `Intl` - [MDN о DateTimeFormat](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/DateTimeFormat).

### 7.2. Общий список «позже»

Это один список для всех недель и месяцев. Переключение периода не создаёт копий. Он не имеет дедлайна обязательного разбора, не переносится по неделям и не входит в их знаменатель. Задача из него попадает в недельный план только после назначения недели или завершения.

### 7.3. Автоматическая смена недели

Использовать одну функцию проверки календаря при старте, фокусе окна, возвращении видимости и из общего таймера напоминаний раздела 10.2. Сначала обработать смену недели, затем напоминания. Отдельный каскадный таймер не нужен.

Алгоритм одного прохода по существующим данным.

1. Определить текущий понедельник. Для всех существующих незакрытых недель раньше него подготовить закрытие. Их строки уже содержат последний сохранённый план и результаты.
2. Найти активные незавершённые задачи с назначенной неделей раньше текущей. В строке исходной недели сохранить результат `pending` и отметить исходящий автоперенос; задача остаётся в знаменателе этой прошлой недели.
3. Переназначить каждую найденную задачу сразу на текущую неделю. Добавить или обновить её единственную строку текущего плана, отметить входящий автоперенос. Сохранить рабочий статус, тип, срок, текст, контакт и чек-лист.
4. Установить `closedAt` у закрываемых недель и сохранить весь результат одной записью. Дата `closedAt` является техническим временем фактической обработки, а граница отчётного периода определяется датами самой недели.

Промежуточные недели не генерировать, копии задач в них не создавать. Если там уже есть заранее составленный план, он закрывается по тем же правилам, а его незавершённые задачи тоже переходят сразу в текущую неделю. Для отсутствующего плана прошедшей недели показать «план за эту неделю не сохранён», без процентов и вымышленных задач. По желанию его можно добавить через исправление сводки.

Счётчик `autoCarryCount` увеличивается на один за фактически выполненное автоматическое перемещение, независимо от числа пропущенных недель. Пример - переход с недели 5 октября на неделю 26 октября даёт один перенос и не создаёт планов на 12 и 19 октября. Подпись «автопереносов - 1» считает операции, а не возраст задачи. Ручные переносы счётчик не меняют.

В целевых колонках перенесённые задачи идут после уже запланированных; между разными исходными неделями сначала более ранние, внутри недели сохраняется ручной порядок. Дата входа в текущий план равна фактической локальной дате переноса.

Повторное открытие не меняет результат - у активных задач больше нет прошлой назначенной недели, а закрытые снимки повторно не закрываются. Соблюдать уникальность пары `weekId + taskId`. «Позже», архив и задачи будущих недель не переносить.

Закрыть также существующие прошлые недели только с целью, завершёнными или снятыми задачами. Пустые недели без данных не сохранять; создавать их при первом содержательном действии пользователя.

### 7.4. Ручной перенос

При переносе из текущей/будущей недели в другую текущую/будущую неделю старая открытая запись получает `membership=withdrawn`, новая - `membership=included` и `result=pending`. В исходной неделе задача больше не входит в актуальный план, но видна в строках «снято с плана» с причиной «перенесено вручную».

Перенос в «позже» имеет ту же логику снятия. Возврат в ту же неделю переиспользует её запись, не добавляет второй экземпляр. Назначать активную задачу в прошлую неделю нельзя; для прошлого существует исправление сводки.

Автоматический перенос отличается от ручного - он сохраняет незавершённую задачу в плане уже закончившейся недели.

### 7.5. Дата компьютера

При перемещении системной даты назад не откатывать выполненные переносы. Если локальная дата сегодня меньше `lastSeenLocalDate`, показать сообщение и приостановить автоматическое закрытие недель до восстановления корректной даты. При последующих сохранениях хранить максимум прежнего `lastSeenLocalDate` и сегодняшней даты, чтобы запись настроек не сняла эту защиту. Просмотр и экспорт доступны. Не запускать массовый обратный перенос.

При смене часового пояса использовать новое местное время для будущих встреч и проверок. Сохранённые даты недель и сроки остаются календарными датами. Исторические даты завершения, сохранённые как локальные даты, не пересчитывать из UTC задним числом.

## 8. Общий план и аналитика

### 8.1. Правило плана

Нет первоначального зафиксированного плана и кнопки его фиксации. План недели включает все её участвующие задачи, в том числе добавленные позднее и входящие переносы. В открытой неделе снятые вручную задачи исключаются из знаменателя. В закрытой неделе автоматически перенесённые незавершённые задачи остаются в знаменателе.

Пример - запланировано 10 задач, добавлено ещё 5, выполнено 9. Результат «9 из 15, 60%». Если две невыполненные задачи вручную сняты с плана до конца недели, результат «9 из 13, 69%», отдельно «снято с плана - 2». Это изменение не маскируется как выполнение.

### 8.2. Показатели недели

После применения фильтра типа определить множество уникальных строк недели с участием `included`. Строки `withdrawn` не входят в него.

| Показатель | Формула или правило |
| --- | --- |
| Всего в плане | Число включённых строк |
| Выполнено | Включённые строки с результатом `done` |
| Осталось | Всего в плане минус выполнено |
| Выполнение | Округление `100 × выполнено / всего` до целого |
| Добавлено на неделе | Включённые строки с причиной входа `created`, `manual` или `restored`, дата входа которых внутри этой недели |
| Входящие переносы | Включённые строки с причиной `auto` |
| Перенесено дальше | Строки, незавершённые при закрытии недели и автоматически перенесённые |
| Снято с плана | Строки с участием `withdrawn` |
| Просрочено | Включённые незавершённые строки с истёкшим сроком |

Если план пуст, показывать «нет задач в плане», без 0% или 100%. При будущей неделе просрочку для активных задач сравнивать с сегодняшней датой, а не концом будущей недели. Для закрытой недели сравнивать срок с концом её воскресенья; задача со сроком в это воскресенье ещё не просрочена на конец недели.

Чек-листы, встречи и общий список «позже» не являются отдельными задачами аналитики. Отмена завершения уменьшает выполненность, а повторное завершение той же строки не увеличивает количество выше единицы.

### 8.3. Месяц

Показать все недели, пересекающие выбранный месяц. В каждой - цель, первые пять задач, кнопка «показать все», количество выполненных и оставшихся, встречи соответствующей полной недели. У граничной недели подписать полный диапазон дат.

Задачи месяца не распределяются по календарной сетке дней. Мини-календарь служит встречам.

Общая месячная аналитика показывает число уникальных `taskId` с действительным результатом `done` и датой выполнения внутри месяца, отдельно рабочие и личные. Если одна задача завершалась после восстановления несколько раз в одном месяце, посчитать один раз; тип взять из последнего действительного завершения внутри месяца. Не суммировать недельные проценты и не показывать общий месячный процент без отдельной определённой базы.

Исправление исторической даты выполнения обновляет показатель соответствующего месяца. Снятые результаты не учитываются. Исторические строки без живой задачи используют свой сохранённый идентификатор.

## 9. История и исправления

### 9.1. Закрытая сводка

Содержит цель, показатели, список включённых задач с их результатами, снятые задачи и отметку наличия исправлений. Обычные изменения текущих карточек не меняют прошлые снимки.

### 9.2. Режим исправления

Кнопка «исправить сводку» открывает явный режим с кнопками «сохранить изменения» и «отмена». До сохранения работа идёт в черновике. Можно изменить цель, название, описание, тип, срок и результат исторической строки, добавить пропущенную строку либо исключить строку из плана.

При отметке исторического выполнения пользователь выбирает дату внутри той недели. По умолчанию подставить воскресенье этой недели. Время выполнения не запрашивать. При снятии выполнения очистить дату результата. Не разрешать дату за пределами исправляемой недели.

Добавление исторической строки создаёт историческую сущность без активной карточки. Можно выбрать существующую задачу, если её `taskId` ещё не присутствует в этой неделе, либо ввести отдельную историческую запись. Зафиксировать, что это исправление прошлого, а не новая задача текущей недели.

Исключение переводит строку в `withdrawn` с причиной `historical_correction`. Не удалять строку физически из истории. Её можно включить обратно.

Все корректировки пересчитывают только затронутые исторические показатели и месячные результаты. Они не завершают, не удаляют и не возвращают текущие задачи автоматически. Если у исправляемой строки есть незавершённая текущая карточка, показать «исправление изменит только прошлую сводку; текущая задача останется на доске» и ссылку на текущую карточку. Это правило особенно важно при завершении задним числом.

После сохранения показать «исправлено» и время последней правки из `correctedAt`. Историю значений до/после и отдельный интерфейс журнала не создавать. До сохранения доступна отмена черновика, после сохранения исправление можно изменить повторно. Прошлые фактические переносы не отменяются задним числом. Если результат исправлен на `done`, сохранённая отметка переноса остаётся фактом истории, но счётчик «перенесено дальше» включает только строки, которые по текущей версии сводки всё ещё `pending`.

## 10. Встречи и напоминания

### 10.1. Встреча

Поля - обязательное название 1-200 символов, дата, время начала `HH:mm`. Дата и время разбираются в местном часовом поясе. Длительности, места, ссылок, заметок и повторений нет.

Создание доступно из календаря и списка. По умолчанию дата - выбранная календарная дата, время не заполнено. Редактирование и создание применяются кнопкой «сохранить», закрытие с изменениями требует подтверждения отказа. Прошлую дату разрешить с подписью «встреча в прошлом, напоминания не будет».

Сортировка по дате, времени, затем времени создания. При одинаковых дате и времени у другой встречи показать названия совпадающих встреч и предложить «изменить время» либо «сохранить всё равно». Собственную редактируемую встречу из проверки исключить. Без длительности нельзя определять частичное пересечение, поэтому не делать такого вывода.

Удаление встречи требует подтверждения и является окончательным. Корзина относится только к задачам. При удалении отменить её ожидаемые напоминания и убрать показанные уведомления.

### 10.2. Алгоритм напоминаний

Напоминания внутри страницы по умолчанию включены. Один `setInterval` с периодом 15 секунд вызывает общую проверку текущего времени; ту же функцию вызывать при старте, `focus`, `visibilitychange` при возвращении видимости, сохранении встречи и включении напоминаний. Не создавать отдельные долгие таймеры на каждую встречу и не считать число срабатываний таймера мерой прошедшего времени.

При каждой проверке заново вычислять разницу между моментом начала встречи и фактическим `Date.now()`. Сначала применить переносы недель. Затем для каждой встречи проверить три случая.

- До начала больше нуля, но не больше 15 минут - показать напоминание с реальным оставшимся временем, округлённым вверх до минуты.
- От начала прошло от нуля до 15 минут включительно - если напоминание ещё не показывалось, вывести «встреча уже началась» с прошедшим временем. Для неполной минуты написать «только что».
- В остальных случаях ничего не показывать.

У встречи хранить одно поле `remindedFor`, равное `date + "T" + time` последнего показанного напоминания либо `null`. Если значение совпадает с текущими датой и временем, повторно не уведомлять. Редактирование названия не сбрасывает поле; изменение даты или времени сбрасывает его в `null`, поскольку это новое назначение встречи. При нескольких событиях показать список и воспроизвести один короткий сигнал. Запись отметок напоминаний проходит через ту же защиту сохранения, что и любые изменения.

Если запись отметки не удалась, не повторять сигнал в этой сессии и показывать общую ошибку сохранения. После перезагрузки без сохранённой отметки повтор возможен; не обещать однократность при недоступном хранилище.

Визуальная карточка остаётся до закрытия пользователем, удаления или переназначения встречи. При перезагрузке уже показанную карточку не восстанавливать и заново не озвучивать. Изменение названия обновляет открытую карточку. В активной вкладке нормальный контрольный предел задержки - 20 секунд; после сна или фоновой паузы сразу перепроверить текущее окно напоминания. Работа при закрытом браузере не предусмотрена.

### 10.3. Звук

Предусмотреть кнопку «включить звук» и «проверить звук». Пользовательский клик создаёт или возобновляет AudioContext. Сгенерировать короткий негромкий сигнал средствами Web Audio API, без отдельного аудиофайла.

Желание пользователя включить звук сохраняется, но реальную готовность звука проверять после каждого запуска. При блокировке показывать «нажмите, чтобы включить звук». Ошибка звука не отменяет визуальное напоминание. Настройка позволяет полностью выключить звук или все напоминания.

### 10.4. Компактный режим

В той же вкладке скрыть доску и показать до десяти ближайших встреч от текущего времени на следующие семь календарных дней, начиная с сегодняшнего. Оставить название, дату, время, добавление, редактирование и кнопку «вернуться к планировщику». Если встреч больше десяти, показать «показать ещё».

Режим сохраняет те же данные и логику напоминаний. Не открывать вторую редактирующую вкладку и не заявлять закрепление поверх других окон.

## 11. Поиск и фильтры

Глобальный поиск ищет одновременно в названиях и описаниях задач. Сравнение без учёта регистра, с приведением `ё` к `е`, удалением крайних пробелов и схлопыванием повторных пробелов. Если запрос содержит несколько слов, каждое должно встретиться в совокупности названия и описания; порядок слов не важен. Контакт и чек-лист в поиск первой версии не входят.

Обновление результатов после паузы 200 мс. Пустой запрос возвращает предыдущее представление. Поиск не создаёт и не меняет задачи.

По умолчанию искать среди активных задач всех недель, «позже» и архива. Отдельные переключатели включают корзину и исторические снимки. Активная/архивная карточка показывается один раз. При включённой истории дополнительные строки группируются по неделе, чтобы было ясно, что это снимки.

Результат содержит название, фрагмент описания, тип, статус/состояние и период. Нажатие открывает соответствующую карточку либо прошлую сводку. В корзине результат предлагает восстановление, но не обычное редактирование.

Фильтр типа - одно значение из «всё / рабочее / личное». Дополнительные фильтры «срочные», «просроченные», «с автопереносом» можно сочетать по правилу И. Кнопка «сбросить фильтры» видна, если что-то выбрано. Отсутствие результатов сопровождается понятным сообщением.

Фильтры типа применяются к доске, архиву, поиску и аналитике задач, но не встречам. Дополнительные фильтры меняют списки, не общий знаменатель недельной аналитики; рядом с ней подписать «итоги по выбранному типу задач, без дополнительных фильтров».

## 12. Цель недели, фраза дня и оформление

### 12.1. Цель и фраза

Главное на неделе - список отдельных пунктов над колонками выбранной доски и недели. Enter или «добавить» сохраняет пункт до 500 символов; общий лимит списка 10 000 символов. Доступны редактирование и удаление с подтверждением. Хранить в goal текстом с разделением строками; прежняя одиночная цель остаётся первым пунктом. Прошлые пункты изменяются через исправление сводки. Пункты не копируются на следующую неделю и не участвуют в проценте выполнения. Несохранённый ввод остаётся в памяти при навигации, при закрытии страницы показывать предупреждение.

Встроить 14 коротких авторских фраз без указания известных авторов. Индекс выбирать детерминированно по локальной календарной дате, одинаково при повторных открытиях в этот день. Они не зависят от просматриваемой недели. Фраза включена по умолчанию, её можно отключить.

По последующим референсам утверждены кремовый фон, оливковые элементы и розовые акценты; дополнительный вариант «графит» заменяет розовые акценты серо-синими. Сохраняются светлые/тёмные карточки, ясная иерархия, скругления и умеренные тени. Название продукта - Planning. Фраза дня находится сверху, набрана тонким курсивным шрифтом.

### 12.3. Настройки

Доступны темы «по времени суток / светлая / тёмная / как в системе», по умолчанию по времени суток (светлая с 07:00 до 20:00, иначе тёмная); выбор основного акцента, фона, рабочих и личных меток; цвет акцента каждого статуса; переименование четырёх колонок до 30 символов. Внутренние идентификаторы и смысл статусов неизменны. Добавление, удаление или изменение числа колонок не предусмотрены. В настройках рядом с переименованием показать исходное назначение статуса.

При пользовательском фоне автоматически выбирать тёмный или светлый текст по большей контрастности. Карточки сохраняют базовые поверхности темы. Если сочетание важных текста/фона не достигает контраста 4,5 к 1, не применять его к текстовой паре и показать объяснение.

## 13. Локальная модель данных

### 13.1. Общие правила

Хранить один JSON-конверт под ключом `personalPlanner.state.v1`. Не использовать `localStorage.clear()`. Разрешён только временный собственный ключ для проверки доступности; удалить его после проверки.

У всех сущностей стабильные уникальные идентификаторы. Использовать `crypto.randomUUID`, если доступно, иначе генератор с проверкой коллизий по всему текущему хранилищу. Идентификаторы не зависят от названия.

Календарные даты имеют формат `YYYY-MM-DD`; время встречи - `HH:mm`; технические отметки времени - ISO 8601 UTC. Дополнительно хранить локальную дату и `weekId` выполнения, чтобы смена часового пояса не меняла историю.

### 13.2. Конверт

Хранить плоский верхний уровень с четырьмя предметными блоками и минимальными служебными полями.

| Поле | Содержание |
| --- | --- |
| `schemaVersion` | Число `2`; версия 1 читается с миграцией в единственную доску main |
| `boards`, `selectedBoardId` | Доски и выбранная доска; подробности в разделе 22 |
| `revision` | Счётчик успешных записей текущего хранилища, для обнаружения устаревшей вкладки |
| `updatedAt` | Техническая дата последней успешной записи |
| `lastSeenLocalDate` | Максимальная локальная дата работы, для защиты от обратного хода часов |
| `tasks` | Массив задач, включая архив и корзину |
| `weeks` | Массив планов и самостоятельных снимков закрытых недель |
| `meetings` | Массив встреч с одной отметкой напоминания у каждой |
| `settings` | Настройки отображения и напоминаний |

Не добавлять `audit`, `lastProcessedWeek`, общий массив `remindersShown` или дополнительные копии всех данных. Потребность переноса определяется по неделе самой задачи. Один конверт сохраняется целиком, чтобы задача, её план и итог не оказались записаны частично в разных ключах. Уплощение структуры не означает разделение записи на множество несогласованных ключей.

### 13.3. Задача

Содержит `id`, `title`, `description`, `type`, `status`, `placement` (`week`/`later`), `weekId` либо `null`, `urgent`, `dueDate` либо `null`, `contact`, массив `checklist` из `id/text/done`, `order`, `lifecycle` (`active`/`completed`/`trashed`), `createdAt`, `updatedAt`, `completedAt`, `completedLocalDate`, `completedWeekId`, `autoCarryCount`, `deletedAt`, `trashRestoreState`.

Для активной задачи `placement=week` требует непрошедшую `weekId` после обработки переносов; `placement=later` требует `weekId=null`. Архив сохраняет неделю результата. Удалённая задача хранит снимок до удаления для восстановления. Пустые необязательные даты - `null`, а не пустая строка.

### 13.4. Неделя и строки плана

Неделя содержит `id`, `goal`, `closedAt` либо `null`, массив `rows` и `correctedAt` либо `null`. Отдельное поле `state` не нужно - `closedAt=null` означает открытый план. Прошлая неделя после обработки переноса имеет закрытый самостоятельный снимок. При создании пропущенной прошлой сводки вручную сразу задать `closedAt`.

Строка является плоским объектом, а не ссылкой на изменяемую карточку. Она содержит `taskId`, `title`, `description`, `type`, `status`, `urgent`, `dueDate`, `contact`, `checklistDone`, `checklistTotal`, `autoCarryCount`, `membership` (`included`/`withdrawn`), `result` (`pending`/`done`), `enteredLocalDate`, `entryReason` (`scheduled`/`created`/`manual`/`auto`/`restored`/`historical`), `completedLocalDate`, `autoCarryOut` и `withdrawReason` либо `null`.

У исходящего переноса `autoCarryOut=true`; входящий определяется по `entryReason=auto`. `withdrawReason` принимает `manual_move`, `later`, `deleted` или `historical_correction`. В строках достаточно чисел прогресса чек-листа, тексты пунктов остаются только у карточки задачи. Историческое добавление вручную по умолчанию получает `status=new`, `urgent=false`, пустой контакт, нулевые числа чек-листа и переносов.

Одна неделя содержит не более одной строки для каждого `taskId`. Идентификатор нужен для исключения двойного счёта, но наличие соответствующей активной карточки необязательно. У самостоятельной исторической записи создать уникальный `taskId`. Ссылку на существующую карточку вычислять поиском по `tasks`, не хранить `hasLiveTask` и не обновлять все снимки при удалении карточки.

Причина входа определяется однозначно. Назначение заранее на будущую неделю даёт `scheduled`; создание в текущей даёт `created`; ручное включение существующей задачи в текущую даёт `manual`; восстановление в текущую даёт `restored`; прямой автоперенос даёт `auto`; добавление через исправление прошлого даёт `historical`. Для автоматического переноса дата входа - фактическая дата обработки. У `historical` дата входа равна понедельнику исправляемой недели, а дата последнего исправления находится в `correctedAt`. При повторном включении снятой строки в ту же неделю сохранять исходные дату и причину входа, обновляя членство и сведения о задаче.

В открытой неделе данные включённой строки обновляются вместе с карточкой. При закрытии они становятся независимым статическим снимком и далее меняются только через явное исправление этой сводки. Снятая открытая строка сохраняет значения на момент снятия, пока не включена обратно. Таким образом, история не теряется при редактировании или удалении текущей карточки, без отдельной системы связей и флагов.

### 13.5. Остальные сущности

Встреча содержит `id`, `title`, `date`, `time`, `remindedFor`, `createdAt`, `updatedAt`. Настройки включают тему, две палитры, подписи статусов, фразу, звук, напоминания, включение буквенных горячих клавиш, состояние сворачивания «позже» и дату последней запрошенной выгрузки.

Не хранить производные проценты как источник истины. Рассчитывать их из строк. Допустимы временные вычисленные значения в памяти.

## 14. Сохранение, ошибки и несколько вкладок

Проверить доступность localStorage при старте записью и удалением тестового собственного ключа. Отдельно различать недоступность API, переполнение и повреждённый JSON.

Каждая предметная операция сначала меняет проверенную копию состояния в памяти, проверяет инварианты, сериализует и выполняет одну запись конверта. Сообщение «сохранено» показывать только после успеха. При ошибке записи оставить актуальные изменения в памяти, показать постоянную надпись «изменения не сохранены в браузере» и действия «повторить» и «скачать копию».

При повреждённом сохранении не заменять его пустым автоматически. Показать восстановление из файла, скачивание исходных повреждённых данных и отдельное подтверждаемое действие «начать заново». Перед сбросом объяснить потерю локальных данных. При неизвестной более новой версии формата открыть экран ошибки с экспортом исходника, не пытаться угадать структуру.

При старте всегда обработать переносы после валидации данных и до первого рабочего экрана. Если перенос нельзя сохранить, оставить режим несохранённых изменений и не сообщать об успешном постоянном сохранении.

### 14.1. Защита от устаревшей вкладки

Поддерживаемый сценарий - одна редактирующая вкладка. Защита обязательна для всех записей, включая автосохранение, переносы, импорт, сброс и отметки напоминаний.

- При загрузке запомнить `baseRevision`. Слушать `window.addEventListener("storage", …)` только для своего ключа и его удаления.
- При внешнем изменении сразу заблокировать запись и автоматические изменения. Сохранить местный черновик в памяти, показать «данные изменены в другой вкладке» с действиями экспорта черновика и перечитывания сохранённого. Не сливать и не подменять данные без действия пользователя.
- Непосредственно перед каждой записью повторно прочитать сохранение и сравнить его ревизию с `baseRevision`. При любом несовпадении, удалении ранее существовавшего ключа или ошибке разбора запись запрещена. Для пустого первоначального хранилища использовать отдельное состояние «ключ отсутствует», а не приравнивать его к ревизии существующего файла.
- При совпадении записать `revision=baseRevision+1`, затем обновить локальную базовую ревизию. Импорт не принимает ревизию из копии как ревизию текущего хранилища; он получает следующий местный номер. Подтверждённый сброс также не обнуляет местную ревизию.
- Если `navigator.locks` реально доступен в выбранном режиме запуска, выполнять чтение, сравнение и запись под одной эксклюзивной блокировкой `personalPlanner.write`. При недоступности не требовать подключения сервера или установки дополнительных средств.

Событие `storage` приходит другим контекстам с общим хранилищем, а не автору записи. Проверка ревизии без межвкладочной блокировки не является атомарной и сама по себе не исключает одновременную запись двух вкладок, прочитавших одну ревизию. Поэтому при недоступной Web Locks API не обещать полноценную конкурентную работу; сохраняется режим одной вкладки с обнаружением устаревших данных. Применимость обеих API к `file:` проверить в Safari и Chrome. Источники - [MDN о событии storage](https://developer.mozilla.org/en-US/docs/Web/API/Window/storage_event), [MDN о Web Locks API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API).

При получении конфликта не проигрывать новые напоминания в этой вкладке, пока пользователь не перечитает сохранение. Обычный просмотр и экспорт своего состояния остаются доступны.

## 15. Экспорт и импорт

### 15.1. Экспорт

Кнопка «скачать резервную копию» формирует UTF-8 JSON с полями `format=personal-planner-backup`, `schemaVersion=2`, `exportedAt` и `state`. Включить все задачи, архив, корзину, встречи с их `remindedFor`, текущие версии недельных сводок с `correctedAt` и настройки. Отдельной истории исправлений нет.

Имя файла - `planner-backup-YYYY-MM-DD-HHmmss.json` по местному времени. Создать Blob и штатную загрузку браузера; освободить объектный URL после запуска скачивания. Показывать «выгрузка запрошена», поскольку приложение не может подтвердить, что пользователь сохранил файл на диск. Экспорт из режима ошибки сохранения использует актуальное состояние в памяти.

### 15.2. Импорт

Выбор файла `.json`, до 20 МиБ. До изменения текущего состояния проверить JSON, формат, версию, поля, типы, лимиты строк, допустимые даты, перечисления, уникальность идентификаторов и недельных строк. Отсутствие карточки для исторического `taskId` допустимо; для активной задачи с назначенной неделей требуется соответствующая включённая строка плана. Не доверять HTML или именам полей из файла; собирать разрешённую структуру явным образом. Отклонять некорректные и несовместимые данные с конкретным сообщением.

Показать дату копии, число активных задач, архивных, удалённых, встреч и недель. Текст предупреждения - «восстановление заменит текущие данные целиком». Кнопки «скачать текущую копию», «заменить данные», «отмена».

После подтверждения подготовить импорт в памяти, обработать пропущенные недели относительно текущей даты и записать одним обновлением. Только успешная запись означает завершённый импорт. При неуспехе сохранить прежнее состояние приложения и предложить экспорт/повтор, не делать частичную замену. Отдельного режима объединения нет.

После успешного импорта открыть текущую неделю, сбросить поиск, закрыть редакторы, применить настройки и перепроверить напоминания. Звуковую готовность всё равно активировать пользовательским действием.

## 17. Состояния интерфейса и доступность

Предусмотреть разные сообщения для пустой недели, пустого «позже», отсутствия встреч, пустого архива, пустой корзины, пустого поиска и списка, скрытого фильтрами. Не заполнять их фиктивными данными.

Формы показывают ошибки рядом с полями и переводят фокус к первой ошибке при сохранении. Подтверждения удаления и импорта называют объект и последствия. Для всех операций есть отмена до подтверждения.

Все кнопки доступны с клавиатуры, имеют понятные названия; иконки имеют текстовые подсказки и доступные подписи. Tab перемещает фокус логично. Escape закрывает меню и безопасные диалоги, но не отбрасывает несохранённые данные без проверки. В открытой модальной форме фокус удерживается внутри и после закрытия возвращается к исходной кнопке.

Нативные HTML-кнопки и поля предпочтительны. Размер обычного текста не меньше 14 пикселей, основного текста карточек - 15 пикселей. Кликабельные зоны не меньше 36 × 36 пикселей. Учитывать `prefers-reduced-motion`; отключать необязательные анимации. Цветовой контраст обычного текста не менее 4,5 к 1 является критерием проекта.

### 17.1. Размеры окна и сенсорное управление

Размеры относятся к CSS-пикселям, а не физическому разрешению экрана. Использовать `<meta name="viewport" content="width=device-width, initial-scale=1">` и не запрещать масштабирование.

| Ширина | Поведение |
| --- | --- |
| От 1200 пикселей | Левая панель с возможностью скрытия, четыре колонки доски; минимальная ширина колонки 230 пикселей, при нехватке места прокрутка только внутри доски |
| 768-1199 пикселей | Левая панель скрыта и открывается кнопкой «встречи» как выдвижная панель; верхняя строка допускает перенос; колонки прокручиваются внутри доски |

На узких экранах действия карточки доступны явной кнопкой меню; переключение статуса и недели не требует перетаскивания. При `pointer: coarse` увеличить интерактивные зоны до 44 × 44 пикселей. Проверки компактных размеров в настольном браузере подтверждают адаптацию вёрстки, а не нативную работу на iPad/iPhone. Не допускать горизонтальной прокрутки всей страницы, перекрытия кнопок и обрезания полей; исключение - явно прокручиваемая доска на ширинах от 768 пикселей.

### 17.2. Горячие клавиши

Не перехватывать `Cmd+N`, `Cmd+F`, `Cmd+W`, `Cmd+R`, `Cmd+Z` и другие стандартные команды браузера и редактирования. Например, `Cmd+N` относится к открытию окна Safari, поэтому для задачи используется отдельная команда. Источник - [Apple о клавиатурном управлении Safari](https://support.apple.com/en-ca/guide/mac-help/mchlgtd_web01/27/mac/27).

| Клавиша | Действие |
| --- | --- |
| `N` | Открыть создание задачи по правилам текущего представления |
| `/` | Перевести фокус в глобальный поиск |
| `←` / `→` | Предыдущая/следующая неделя либо месяц, только в соответствующем основном представлении |
| `T` | Вернуться к текущей неделе |
| `Escape` | Закрыть верхнее меню/панель либо отменить перетаскивание, с проверкой несохранённых данных |

Буквенные команды определять по `KeyboardEvent.code` (`KeyN`, `KeyT`, `Slash`) для одинаковых физических клавиш в русской и английской раскладках; подсказки показывают обе буквы «N / Т» и «T / Е». Они выполняются только без модификаторов, вне `input`, `textarea`, `select`, `contenteditable`, кнопок и интерактивных виджетов, когда нет открытого диалога/редактора. Не обрабатывать события с `isComposing` или `repeat`. Стрелки не должны мешать управлению полями и календарём.

`preventDefault` вызывать только для фактически выполненной команды. Буквенные команды включены по умолчанию, в настройках есть переключатель «горячие клавиши». Выключение отключает N, T, / и навигационные стрелки приложения; стандартные Tab, Enter и Escape сохраняются. Подсказки доступны через помощь. Все действия остаются доступными мышью и обычными кнопками.

## 18. Валидация и безопасность данных

Пользовательский текст и содержимое импорта выводить как текст через безопасные DOM-операции. Не выполнять HTML, скрипты, CSS или JavaScript из названий, описаний, файлов и настроек. Не применять `eval`, `new Function` или пользовательский текст в `innerHTML`.

Сроки и недели валидировать календарно, включая число дней в месяце и високосный год. Разрешён диапазон дат 1900-2100. Время - часы 00-23 и минуты 00-59. Максимум 10 000 задач, 10 000 встреч, 10 000 недельных сущностей и 100 000 строк истории на один импорт; это верхние ограничения валидации, а не обещание вместимости localStorage.

Не удалять историю автоматически при нехватке места. Показывать понятную ошибку и экспорт. Любое ограничение объёма не должно приводить к молчаливому усечению.

## 20. Требования к сдаче реализации

Передавать три готовых файла приложения и краткую инструкцию открытия. Инструкция может быть текстом в ответе и разделом помощи внутри страницы, без обязательного четвёртого файла приложения.

Предоставить перечень выполненных приёмочных проверок, фактические версии браузеров и среды, а также отдельно непроверенные ограничения. Не подменять работающие функции декоративными кнопками. Если обязательный сценарий не реализован, считать реализацию незавершённой и явно указать его. Настоящий виджет рабочего стола и работа при закрытом браузере не являются обязательными критериями этой версии по ограничениям раздела 4.

Готовность означает, что данные сохраняются в проверенной среде, редактирование и переносы не создают дубликатов, история исправляется осознанно, формулы воспроизводятся по примерам, резервная копия восстанавливается и интерфейс проверен визуально.

## 22. Согласованные дополнения версии 2.0

Эти требования дополняют исходные разделы. При различиях названий и оформления приоритет имеют утверждённые здесь изменения.

- Доски независимы в одном хранилище. Создание до 100 досок с уникальным без учёта регистра непустым названием до 60 символов, выбор и удаление с подтверждением. Последнюю доску удалить нельзя. Удаление доски удаляет её задачи, архив, корзину, встречи, недельные строки и заметки. Общие настройки остаются. Задачи, встречи и недели имеют boardId; уникальность недели определяется boardId + понедельник. Экспорт включает все доски. Два человека на разных компьютерах используют независимые локальные данные; аккаунтов и синхронизации нет.
- У каждой доски background.from/to (HEX), backgroundStyleVersion и appearance (soft/graphite). Фон и вариант можно выбрать отдельно. Общая пользовательская палитра имеет приоритет; явная настройка фона доски отключает общий фон текущей темы. Сброс оформления с подтверждением сбрасывает также оформление досок, не затрагивая их содержимое.
- Помимо недели и месяца доступен календарный квартал. Показывать число уникальных выполненных taskId за квартал, рабочие/личные результаты и столбики по месяцам. Повторное выполнение одной задачи внутри квартала считать один раз в общем итоге; сумма отдельных месячных значений может быть больше. Общий квартальный процент не рассчитывать без базы плана.
- Отметка reportImportant («для отчёта») есть у задач и исторических строк. Она помогает выделить важные результаты; изменение отметки синхронизирует только этот признак в связанных снимках, не их содержание и факт выполнения. Отчёт содержит выполненные задачи с описаниями и отметками, по месяцам. У каждой доски monthNotes: месяц YYYY-MM-01 и текст до 10 000 символов, явная кнопка сохранения. Черновики сохраняются при навигации в памяти, закрытие страницы предупреждает о них.
- Круг выполнения недели постоянно виден отдельно от подробных показателей. Подробная «статистика недели» свёрнута по умолчанию, settings.statsExpanded хранит выбор. «Всего за неделю» включает выполненные и открытые задачи плана, «открытые задачи» показывает оставшиеся. Математика раздела 8 сохраняется. Месяц показывает столбики выполнений по неделям, квартал - по месяцам.
- Активный дедлайн выделен полосой и текстовой датой с годом: будущий серо-синий, сегодня янтарный, просроченный красный. При смене дня обновлять состояние. Архив не выделять как просроченный. Календарь встреч остаётся отдельным; задачи в него не добавляются.
- Новые настройки имеют значения по умолчанию при чтении прежних копий: themeMode=auto, statsExpanded=false, customPalettes и paletteBackgrounds для каждой темы=false. Старое поле theme и ключ personalPlanner.state.v1 сохраняются для совместимости. Копии версии 1 мигрируются в памяти; запись только через обычный механизм сохранения.
- Для передачи другому человеку комплект содержит index.html, style.css, script.js и README.md. Пользовательские резервные копии, Git и тестовые данные в него не входят.

На широком экране доступна кнопка «скрыть встречи / показать встречи».
Скрытие освобождает ширину для задач. Выбор хранится в settings.meetingsCollapsed,
по умолчанию false, и восстанавливается после обновления страницы.
Ниже 1200 px кнопка открывает выдвижной календарь, закрываемый кнопкой или Escape.
Скрытие не отключает напоминания и не меняет встречи.
